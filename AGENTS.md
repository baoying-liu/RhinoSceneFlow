# RhinoSceneFlow development

- Product scope: AI assets → physical-scale materials → planting → view-layer export → postproduction. Current implemented slice is layer-RGB PSD export, independent hard-shadow PSD export and Platform automation.
- Keep geometry/projection/PSD serialization in Core; Rhino SDK, commands, preferences and the public JSON API belong in Plugin. Commands and automation call ExportService.
- Depend on the user's installed Rhino-MCP-Platform. Do not start another MCP server, patch Platform private implementations, or edit Codex MCP configuration for this project.
- Automation entry point: `RhinoSceneFlow.Plugin.McpApi.Execute(JSON)` via Platform `run_python`. Update docs/MCP.md with API changes.
- Test only in RhinoDevSandbox channel B (`1cee488700ad42f59492743cc4a2a3fe`), management MCP 19540. Discover the actual Rhino MCP port from B's Monitor record and verify PID. Do not assume the launcher's selected UI tab is B.
- Prefer MCP and file-based PSD inspection; avoid taking the user's mouse. Use no save dialogs in automatic exports.
- Default B export directory is this project's `artifacts/exports`. Generated PSDs, models, receipts and previews stay under ignored artifacts. Never commit credentials.
- Build/package with scripts/Build.ps1. Validate real exports with scripts/Smoke-Rhino.py (requires a fresh empty B document) and scripts/Verify-RhinoPsd.py (independent psd-tools decoder).
- Manage test instance builds/restarts through the sandbox MCP. Retain failed/unknown exit evidence; do not force-kill instances or change another channel.
- No formal Rhino deployment is implied by sandbox test work. Preserve document geometry, attributes, selection, view and modified state during exports.
- Update docs/Validation.md and docs/Sandbox-B.md with actual evidence; distinguish independent file decoding from opening Photoshop itself.

- Shadow backend: pinned geometry3Sharp 1.0.324 (Boost). Keep the managed dependency beside the RHP. No native runtime or separate MCP server.
- Known v0.3 accuracy failure: tangent-plane normal offsets can move a shadow ray past a nearby occluder. Do not treat this heuristic as an acceptable fix for terminator artifacts. Preserve geometric visibility; separate shading normals from occlusion and explicitly validate contact/gap shadows. Do not hide geometric artifacts with blur or threshold image cleanup.
- Shadow verification: scripts/Test-ShadowRhino.py after Test-ComplexRhino.py; independent scripts/Verify-ShadowPsd.py. Retain failed visual/oracle evidence and verify curved receivers as well as planar ground.

- Accuracy audit: scripts/Research-ShadowNative.py, Research-ShadowPlanar.py and Research-ShadowContact.py are B-only research prototypes. Verify-ShadowAlternatives.py records a known CURRENT-backend failure; researchChecksCompleted does not mean currentBackendAccurate. See docs/Shadow-Alternatives.md.

- v0.4 adds a separate CPU z-fail volume backend (`backend: volume`, `RhinoSceneFlowExportShadowVolumePSD`). Keep the legacy ray default explicit; it still has the known offset failure. Preserve closed caps, off-camera casters, far-plane handling, exact shared-edge cancellation and fixed subpixel/top-left coverage. v0.4.1 uses smooth normals to select uncertain curved samples and for optional form shading; actual shadow refinement queries owned source-geometry snapshots. Do not displace points along smooth normals. Respect trims, local double precision and grazing-ray root convergence. See docs/Shadow-Accuracy.md. Validate Test-ShadowAccuracy.py / Verify-ShadowAccuracy.py including partial-coverage boundaries, plus Test-ShadowVolumes.py, Probe-ShadowVolumeMesh.py and Verify-ShadowVolumes.py. Keep v0.4 historical artifacts separate from volumes-v041. Do not claim universal analytic accuracy or hide defects with image cleanup.

- v0.5 panel command: RhinoSceneFlowPanel. Use native Eto and ImageView raster previews; never instantiate ViewportControl (it leaked floating Custom view windows in v0.5); preview modes do not change PSD pass content. Current material pass is layer RGB, not textured materials. One PSD per Named View, Shadow above material pixel layers. Use IPsdImage/LayerStack to preserve independent pass alpha and validate with an independent PSD compositor.
- Named View batches use standalone `new RhinoViewport()` (the copy constructor retains ParentView and resizing it changes the main view). Preserve the main view and use its visibility filters explicitly. Read document state and snapshot owned source geometry on the UI thread; workers must not access RhinoDoc or live document geometry. Keep all channels at the same tessellation quality and camera.
- Preflight every target before rendering. Interactive collisions: Yes=overwrite, No=001/002 numbering, Cancel=abort preflight. API defaults to numbering. Reserve sanitized names case-insensitively so two views in a batch cannot overwrite one another. Keep PSD atomic writes/cancellation. Panel controls refresh by NamedViewId and must retain per-view dimensions while open.
- Panel tests: Test-ExportPanel.py, Test-ExportPanelUi.py, Verify-ExportPanel.py; asynchronous start/poll tests Test-/Check-ExportPanelAsync.py and Test-/Check-ExportPanelCancel.py. Do not block the Rhino UI waiting for a worker task. Artifacts live under artifacts/rhino-B/panel. WPF layout-only captures exclude the native viewport HWND; inspect native preview captures separately.

- v0.5.1 direct-sun shadows: panel and volume command/API default includeFormShading=true; explicit false retains cast-only masks and legacy ray defaults remain unchanged. No reflections, GI or AO. Preserve original-surface uncertainty checks; safely backlit interiors need no light visibility query. Cached full closed spheres and trimmed planar face queries must retain bounds/trim tests. Test-DirectShadow.py / Verify-DirectShadow.py and Test-PreviewWindows.py cover self shadow and view/window lifecycle.

- v0.6 replaces the single-preview panel with two-column per-Named-View cards. See docs/Workbench.md. Settings, layers, camera and sun are independent per view, persisted outside RhinoDoc. Size and layer copy buffers are separate deep copies in process; do not use the OS clipboard. Previews never create native RhinoViews. Only explicit WriteBack modifies a Named View camera.
- WorkbenchService uses temporary UI-thread CaptureScope for native display RGB and sunlight, restores camera/display/sun/modified state in finally, then snapshots geometry to owned workers. Derive orbit pivots from saved Named View data identically for native and standalone viewports. UI updates between batch items must marshal to UI. Legacy NamedViewExportService contracts remain supported.
- Workbench channels tile at 1024 with 2-pixel halos and owned per-worker surface query clones released between tiles. DiskPassImage streams channels; ConfiguredStack preserves real RGB, isolated material groups, PSD blend and opacity. Workbench supports 64..8192 per side and PSD size limits, legacy commands retain 8-million-pixel limit. Never raise dense raster limits to implement 8K.
- Current panel harnesses: Test-Workbench.py / Verify-Workbench.py, Test-WorkbenchDetails.py, Test-WorkbenchAsync.py / Check-WorkbenchAsync.py. Old v0.5 UI reflection harnesses target the historical panel. Retain numeric/tangency differences in reports; independent PSD decoding is not Photoshop UI validation.
