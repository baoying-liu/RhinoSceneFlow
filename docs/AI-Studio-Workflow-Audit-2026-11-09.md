# AI Studio 流程与 UI 审计 · 2026-11-09

本轮以公司 B 通道、0.22.0、小山地建筑 `01 Hillside Axon.psd` 为案例。目标是梳理流程，讨论后再重构；本轮只补 Rhino 原生工具栏，没有改变生图语义。

## 证据与范围

- 独立工程：`Hillside · 流程审计 2026-11-09`，ID `f5a530f8a7a0414c8b1c092075bd1b9f`。
- 原 PSD 为 1200×900、13 个图层/组。本轮复制导入，不改源 PSD、材质库或原模型。
- 真实无界面 Edge 检查导入源图、创建子级、应用父级、列表对比、画布和设置；5 张截图，零 page errors。没有使用系统鼠标。没有新生图请求，不能据此评价新生成的画质。
- 按实际 start 路径组装当前子级输入，离线运行同一 raster prepare：1,080,000 像素中 938,636 可改、141,364 受保护；默认 blend=100、detail=65、freedom=15。这个案例并非默认把几乎所有像素锁住；不能把以往“变化小”一概归因于掩码。
- 截图/事件和输入证据：`artifacts/ui-audit-20261109/{browser-audit.json,01-root.png,02-draft.png,03-applied-parent.png,04-canvas.png,05-settings.png,payload/audit.json}`。

## 现在真正执行的流程

1. 导入原 PSD/图片，保存不可变输入。原始节点上的可编辑设置是下一次创建子级的模板，并非允许更新原文件。
2. 创建子级只建立 pending 草稿，没有调用模型。源图的描述/参数传给第一代草稿；从已生成图分支继承参数、清空描述。同级使用所选节点的父级作为输入。
3. 白板保存输入快照，但还没有 AI 结果。“应用父级”只是为草稿放入父级像素，方便标注，不代表生成完成。
4. 更新时解析最新有效父级（包含归档跳过说明），冻结输入版本、草稿配置、空间上下文和参考图。即使在一个已有结果上点更新，主要输入仍是它的有效父级，不是当前结果。
5. 整图任务准备 clean input、考虑框图示、可修改 mask、可选参考合板，交给已有 image-only runner。模型输出经过裁切/回填，恢复受保护像素和原 alpha，发布到当前草稿 ID；成功后锁定，旧结果进入备份。
6. 高清任务要求父级是已完成的生成图；放大该 anchor、分块处理、诊断/人工复核、融合。它不是不加条件地对当前所见图片点一个“下一步”。
7. 导出为扁平 PNG/JPEG/WebP。PhotoCraft 编辑参考层、画布文字/箭头等是指导，不直接烧录到导出的结果。

代码依据：`board_store.py` 的 branch/effective/publish，`board_api.py` 的 snapshot/start/work，`board_render.py` 的 prepare/finish/detail/export，以及 `web/postproduction/src/main.jsx`。

## 主要问题

| 优先级 | 发现 | 用户感受与实际后果 | 建议 |
|---|---|---|---|
| P0 | 更新输入是父级，而屏幕主图是当前结果 | 用户以为在现图上修一个细节，实际是在上一输入上重做 | 持续显示“输入：父图·版本”；把更新称为“按此输入重新生成”。“继续修改这张结果”明确创建子级 |
| P0 | 高清按钮看似阶段切换，后台按父级校验 | 第一代结果切高清仍可能因父级是源图而被拒；必须先新建子级 | 结果页提供“高清输出”，自动准备以本结果为输入的高清草稿，并显示预计图块/输出；保留确认再调用 |
| P0 | 自动保存、黄色草稿、锁定、撤销修改、Undo、图片备份并列 | 不清楚是否保存、是否生效、哪一个能恢复 | 明确区分“配置已保存，待生成”与“结果已完成”；撤销编辑、放弃本次草稿、恢复结果分别命名；容量管理移入历史 |
| P1 | 操作层级倒置 | 1800×1100 下描述在参考层和空参考列表后面，常用设置更靠下 | 固定三块：输入摘要、修改要求、生成按钮；参考与标注次之，低频选项收起 |
| P1 | 双重编辑入口 | 源图有完整模板，子图又出现相同完整参数；白板还有应用父级/锁定/删除白板/普通删除 | 源图以“创建方案”为主；详细编辑集中到草稿。原模板可保留但收起。白板阶段仅显示适用操作 |
| P1 | 模型指令、硬保护和像素混合像同一种强度 | detail/freedom 是提示词，mask 是硬回填，blend 又是像素混合；用户难预测变化幅度 | 分成“生成意图”“保留范围”“结果呈现”；混合移到对比/输出，解释其是否进入后续输入 |
| P1 | PhotoCraft 层看起来像结果却不导出 | 眼睛控制预览叠加，enabled 控制 AI 指导，两者独立；所见与下载可不同 | 明示“参考叠加预览，不计入输出”；眼睛标“显示参考”，AI 开关标“生成时使用”；导出前展示真实输出预览 |
| P1 | 框内自动吸纳内容缺少提交前总览 | 任意摆放可能使素材参与其他图片，5 个参考（含编辑层）会被后台拒绝 | 生成前简明显示目标输入、实际标注/参考、mask；显示参考预算和被忽略内容，具体上限错误就地提示 |
| P2 | 同一操作分布在顶部、检查器、右键，且没有一致分工 | 原图、草稿、完成图上出现不适用/禁用按钮，用户靠试错 | 顶部放浏览/文件，右侧放当前任务，右键放快捷副本；主按钮随状态明确变化 |
| P2 | 文案残留 | 原生后期面板仍写“先测试分块，再批量生成”，但主流程已经是先整图 | 统一为整图探索 → 定稿 → 高清输出；帮助文案跟随当前任务 |
| P2 | 实现耦合 | main.jsx 集中传输、状态、编辑、视图、PhotoCraft、历史与任务，局部修改影响范围大 | 分离任务状态、输入解析、草稿、预览、画布、参考和历史控制器；用同一个有效输入解析器供显示与提交使用 |

补充：当前 blend 在预览/导出按当前 input/逻辑父级取图，而生成 start 先把 image/parent 都替换成最新有效父级。尤其遇到归档和父级更新时，不能把这个滑块解释为可靠的“AI 修改强度”；需要专项统一输入语义。本轮未修改它。

## 建议的用户流程

保留列表与画布两个视图，二者操作同一个任务和相同节点；不增加第三套编辑状态。

`导入原图 → 创建方案草稿 → 描述/标注 → 检查输入 → 生成 → 对比 → 继续修改 / 尝试另一方案 / 高清输出 → 导出`

- **原图**：保留文件后缀、PSD 图层；主按钮“创建方案”。原像素不可更新，模板可编辑。
- **草稿**：主按钮“生成图片”；输入缩略图与来源始终可见。空白结果仍为空白，提供明确的输入底图显示开关辅助标注。避免把底图当作生成成果。
- **完成结果**：默认锁定。主要选择为“继续修改”（子级，输入为此结果）、“另一方案”（同级，输入为同一父级）、“高清输出”（以此结果作 anchor）。高级入口保留“解锁并重新生成此节点”，但明确这是重做原任务。
- **任务中**：显示准备输入/排队/生成/回填/复核的真实状态与耗时，允许取消；失败保留草稿，重试不伪造成功。
- **输入变化**：紫色提醒仍保留，但在输入摘要显示哪个版本变了、将用哪个版本重做；黄色仍表示配置待生成，同时有文字标签。
- **历史与归档**：保留可逆归档、输入溯源和容量策略，默认隐藏复杂管理；快满时再提供清理/扩容，不混进常规绘图路径。

## 侧栏与画布分工

右侧“生成”页先显示输入来源和一句任务状态，其后是描述、处理预设和主动作。常用预设可用“保真润色 / 细节补全 / 概念深化”，细节和自由度收在可展开区域；禁止把提示词强度声称为精确模型参数。

“参考与标注”页统一列出框内实际内容：外部参考、PhotoCraft 编辑指导、文字/箭头、可改/保护区。画布工具负责空间操作；同一份素材只能有一个明确身份。PhotoCraft 继续作为单份可替换的编辑指导，不进入结果历史。

“记录”页集中结果备份、生成收据、输入版本和归档。Undo/Redo 只管编辑，结果切换仍用不可变备份。

考虑框继续决定上下文，图片像素框决定输出；二者在提交预览中必须明显分开。保留实时连线、避让、独立折叠、右键平移、手写笔、行内文字和双向参考选择。

## 实施顺序（待讨论）

1. 先统一“当前看什么、生成用什么、结果存在哪”的摘要和动作命名；修正高清入口及旧文案，不动源像素/历史格式。
2. 重排侧栏，把主任务放首屏；把参考显示与实际输出分开；复用既有后端能力。
3. 统一有效输入解析，增加无模型的提交预览和实际 mask/参考预算；覆盖归档、上游变化、编辑参考、备份 checkout 的显示/提交一致性。
4. 最后拆分前端控制器，保持文件兼容。验证至少包含原 PSD→第一稿、结果→子级、结果→同级、原输入变化后逐级更新、归档跳过、高清、取消重试、导出所见像素一致性。

以上为审计与设计建议，未宣称这些 UI 重构已经完成。以用户确认的流程为准，不删除既有保护机制，也不为了“简单”牺牲溯源。
