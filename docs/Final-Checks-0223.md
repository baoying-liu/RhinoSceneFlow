# 0.22.3 · 最终成图检查与 4K 验证

## 本次范围

只补必要的最终结果检查、失败保护及不同图像特征的回归测试，没有再次整理整个界面或增加画板管理功能。沿用原厂 Rhino Platform JSON MCP，所有实际案例操作在公司 B。

## 最终检查

- 完整融合后重新读取 PNG，独立比较保护区 RGB 和整图 alpha；这类像素完整性错误直接拒绝发布，不能手动跳过。
- 在最长边 1600 的预览中比较融合边界与候选图自身的梯度，检测意外接缝；相对候选图检查局部纹理损失，以及缺少候选图支持的新增轮廓。
- 这些图像诊断是启发式提示。触发时进入最终图待检查状态，不自动替换上一张可用图；检查页面显示融合图及原因。
- 用户可明确确认已经检查过的最终图，必须提供当前 fusionId；过期的确认会被拒绝。原始诊断仍保留，确认记录为 reviewAccepted。

## 回归证据

`Test-FinalFusion.py` 在独立合成场景中验证白模窗框、密集植物、重复材质纹理和 4096×3072 的一致重建；注入黑色接缝、模糊、重复轮廓及保护像素/alpha 破坏，验证相应警告或完整性拒绝。这些测试不调用模型，不冒充真实 AI 出图。

`Test-FinalReview.py` 验证待检查结果不更新 latestRun、过期确认拒绝、显式确认以及完整性错误不可放行。真实 headless Edge / HTTP 夹具进一步验证确认前旧图不变，确认后更新并保存只读备份。

真实 2K 四块候选在新检查器中重放，无新增图片调用：没有异常接缝/模糊，未支持边缘比例约 0.00012，保护像素及 alpha 变化均为 0。之前的来源追踪、蒙版、取消、工作流、重新融合回归继续通过。

## 真实 4K

目标 4096×3072，保持 Hillside 原图 4:3 比例。以已批准的整图作为输入，图块最大边长 1536、上下文 128，计划 12 个均衡核心块。实际候选尺寸、调用次数、失败/待检查记录和最终 PNG 以 `artifacts/rhino-B/final0223` 内的任务及验证记录为准。

不把简单缩放或不完整融合当作 4K 成功；只有实际任务完成、输出独立解码尺寸正确、保护检查通过并查看整图后，才作为结果交付。保留旧 PSD、旧 2K 图及测试失败证据。
