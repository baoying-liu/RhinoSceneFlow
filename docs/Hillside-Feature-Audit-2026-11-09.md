# Hillside AI Studio 实例测试 · 2026-11-09

## 结论

以公司的沙盒 B、RhinoSceneFlow 0.22.1 和真实 Hillside PSD 完成 AI 后期工作流测试。27 项 MCP/API 检查、11 组实际网页交互、6 组画布/任务交互最终通过，另通过真实 PhotoCraft 编辑往返和参考图库交互。没有操作系统鼠标，没有安装更新、重启 Rhino 或修改产品逻辑。

**功能通过不等于出图质量通过。** 高清分块有树木漂移及明显融合痕迹；箭头/文字也不能代替硬蒙版。当前仍不宜把高清结果当作稳定交付成果。

本轮范围是当前讨论的 AI 后期 Studio：PSD 导入 → 整图 → 标注/参考 → 分支/更新 → 高清 → 导出。没有把 Rhino 建模、UV、素材生成、种植编辑和重新导出 Rhino PSD 算成本轮已测试；使用的是仓库中已有的真实案例 PSD。

## 用户体验和效果问题，按优先级

### 1. PSD 导入画面与实际生图底图不完全一致

导入使用 `psd.composite()`，生成准备使用 `composite(force=True, layer_filter=...)`。本案例没有 exclude 图层，仍产生像素差异。生成结果相对真正准备底图的保护区域变化为 0、alpha 变化为 0；相对导入预览的保护像素却有 89,185 个变化，20,009 个 alpha 值不同。主要是合成路径差异，不能把这部分算成 AI 重画。

建议统一合成来源；需要重合成时，应明确展示当前实际底图，不能只用历史导入预览让用户判断“保护是否生效”。证据：`pixel-verification.json`、`original.png`、`actual-generation-base.png`、`whole-A.png`。

### 2. 高清分块目前不稳定，不能直接交付

边缘块宽度仅 192 像素、上下文不足；两次生成的结构距离 P90 分别约 31.2、32.3 像素，均被系统拦下。看图可见树的位置/冠形变化。最终融合的右侧还有明显淡化、重叠及接缝。

为了验证接受与融合按钮，**仅在独立测试画板中功能性接受了这个已知有问题的块**；输出命名为“功能验证（存在结构漂移）”，不代表质量批准。

建议先改窄边缘块分配及最小上下文、保持全图锚点可见、增强接缝检查；质量不合格时保留整图批准结果供交付，不用劣化的融合结果替代。证据：`hd-review.json`、`hd-review-retry.json`、`hd-tile2-base.png`、`HD-functional-not-quality-approved.png`。

### 3. “箭头 + 只改这里”缺乏硬范围，容易误解

标注子图的实际 editablePixels 是全部 1,080,000 像素，尽管描述只要求改立面，草地、树也被重画。标注理解能力不等于像素保护。另一张用闭合 edit/protect 区域的真实更新，区域外完全一致。

建议生成前明确区分“语义指导”和“硬编辑范围”。发现局部指令但没有局部蒙版时，在输入检查里显著提示“当前仍允许全图变化”，可快捷补画范围，避免让用户误以为箭头自动产生局部蒙版。

### 4. 参考区撤销后自动收起

删除当前参考图后取消资源选择，参考区可能收起。撤销恢复了资源，但用户还要再次展开才能继续操作。建议独立持久化用户手动展开状态，并在撤销恢复参考图后保留选中及可见状态。

### 5. 小的命名和设置阻力

- “高清”允许选择 1024，而本例输入长边 1200，实际是缩小。建议小于原尺寸时显示提示，并把入口解释为“分块细化/输出尺寸”。
- 备份限制为全局设置加单图容量，当前信息分散。建议放在一处说明“已有 / 可留、满时如何处理”。
- 关闭按钮无障碍名称固定英文；应随语言一致变化。
- 归档后使用的新输入和说明已有 preflight，但建议在任务摘要直接展现跨过了哪些节点，减少查找历史的成本。
