# 植物素材与种植（v0.15.0）

v0.16 种植 UI 已升级为[参数化种植对象](PlantGroups.md)。下文的独立点放置及尺寸限制描述 v0.15 兼容路径；新组合保存参数、手工附着和承载面关联，支持整体编辑。

**本轮状态（2026-10-30）**：生成／实际来源验证、图片参考与复用、AI 整理、种植与三种 PSD、阴影、New/Open 已在 B 测试。最终 Alpha 轮廓预览已在 B 安装并完成透视／俯视检查，此前重叠卡片的矩形缺口已消失；独立 PSD 解码确认植物组置顶和完整 Alpha。部署与关闭／重启记录见 Sandbox-B.md，详细证据见 Validation.md。

沿用现有 AI 素材对话框与图片上传，不增加第二套聊天。描述具体植物，或描述形态、环境、地区；系统先识别任务，再实际联网核实真实物种，记录学名、科、属、品种、资料来源与核实时间。明确植物名称不替换成别的物种；名称或参考照片不足以可靠识别时，返回候选而不生成。学名、科名必须同时出现在实际获取的受支持植物资料页面中；只有模型填写网址、不实际搜索，或页面验证失败，不会继续图像生成。

目前来源支持 Kew/POWO、WFO、Missouri Botanical Garden、NC State、USDA、GBIF、RHS 的具体 HTTPS 条目。网页仅作资料，不作为执行指令；只允许受支持域内重定向，限制抓取大小与时间。联网搜索采用本次独立 Codex 执行的 `web_search="live"`，不改用户全局配置，依据 [OpenAI 官方搜索文档](https://learn.chatgpt.com/docs/web-search)。沿用现有 ChatGPT 登录，无新增 API key 或 MCP 服务。

默认优先复用植物库。先按已核实的物种/品种匹配，再结合标签、描述与实际候选缩略图比较形态和季节；没有合适素材才调用真实 image_gen 生成新 PNG。上传图片同样参与识别与外观匹配。生成是植物图像，不是无缝材质；要求完整植株、真实透明 Alpha，无地面、文字、水印或烘焙地面阴影。入库验证 Alpha，裁去透明边距，以底部可见像素估计基部横向锚点。参考高度可改，不声称从无比例尺照片测量尺寸，也不保证生成图片具有植物标本级鉴定精度。

植物库位于所选本地材质库的 `Plants` 子目录，跨文档、同机多进程共享；复用已有文件锁、原子提交、版本冲突与目录整理恢复机制。材料库与植物库分开。植物库可按名称/学名搜索、科/属/标签筛选，并显示透明素材预览。AI 整理审视整库，统一名称和标签，分类保持已核实的科名；不得改写物种身份、来源、图片、尺寸或外观版本。实际生成素材会显示在原聊天中；通过按钮进入种植页，不自动跳走聊天。

## 放置和朝向

点选位置放置，或选择一个曲面/Brep/网格区域散布。散布对三角网格面积加权采样，支持数量、米制最小间距、种子、等比例随机缩放、随机水平镜像；密度受间距限制时明确报告实际数量，不强行重叠。曲面采用显示网格近似，密集区域最多 200 万次候选尝试。一次放置最多 10000 株。

植物在文档中是带持久元数据的点锚点，可选择基部并使用 Rhino Move 移动、复制、删除及撤销。**高度、随机比例用于放置时；Rhino 对点的 Scale 不会改变植物尺寸**。高度在库内调整后重新种植；本版尚无对已有植物的批量尺寸编辑，也没有 3D 植物、地形坡度过滤或碰撞体积模拟。

全局朝向：自动、只绕世界 Z 轴、完全朝向相机。默认自动在仰/俯视角约 60° 时切换，使用 ±5° 平滑过渡而非临界开关；角度可改。以基部为支点。每个视口独立算几何，不旋转或反复改写文档对象；Named View 导出使用自己的相机。完全朝向采用屏幕平面方向。高角度看的是转向相机的平面立面素材，不是生成的新俯视树冠。

镜像同步翻转非居中基部锚点，避免树干离开种植点。完全俯视时平面可能与地面共面：CPU 不把同深度地面当成前方遮挡；原生绘制使用相对植物尺寸 1e-5 的显示深度分离避免闪烁，不修改存储坐标。

原生预览采用按 Alpha 生成的透空几何：256/512 栅格轮廓、8 档透明度、行程合并并缓存网格，重复植株复用几何。透明区域不产生矩形深度遮挡。原生 RGB 预览缓存向透明区域延伸边缘颜色，避免采样黑白边。B 中经典贴图产生矩形底板；PBR 底色 Alpha 改善单株，但重叠卡片仍有矩形透空问题，不能当作最终实现。PSD 和独立阴影始终采样完整原 PNG Alpha；原生预览的轮廓细节、光照、透明度分档与导出有差异。

## PSD

新视图、首次迁移的旧配置默认在最上方添加植物通道；允许用户随后调整、关闭、删除或复制配置。植物从材质、图层颜色和原生显示模式底图中排除，避免重复烘焙。建筑等**非植物**物件以深度裁切植物；不反过来裁掉下面的材质底图。

| 模式 | PSD 结构与遮挡 |
| --- | --- |
| 单株 `individual` | 植物组 → 学名子组 → 单株。只裁切非植物遮挡，植物之间不裁切；同种内默认近株在上。不同学名组的全局交错顺序不能仅靠组顺序完全表示，可在 PSD 手动调整。 |
| 按种 `species`（默认） | 植物组 → 每个学名一个像素层。按实际逐样本深度、透明度计算所有植物可见贡献，处理不同物种交错遮挡。 |
| 全部 `all` | 植物组 → 一个植物像素层，按实际深度合成全部植物。 |

合并模式把可见贡献按组转换为正常 Alpha 图层，保持与全部合并的合成结果一致（8 位量化误差约 1–2）。PNG 采样使用预乘 Alpha，避免透明像素的 RGB 污染边缘。四子样本抗锯齿，1024 分块、每组裁切暂存，避免为每株分配整幅 8K 图片。完全被裁掉的植物不产生可见像素层。

单个分块的植物图层裁切缓存超过 128 MiB 时拒绝，提示改为按种／全部合并；单视图独立 PNG 快照限制 512 MiB，PNG 与原生贴图缓存分别有 256 MiB 预算。没有借扩大内存来承诺无限密度或无限分辨率。

独立阴影通道默认包含植物透空投影，按 PNG Alpha 采样太阳射线，接收面使用非植物网格，与既有建筑阴影合并。可以关闭。没有反射、GI、AO，也没有植物之间的立体冠层光照；二维素材阴影会随相机朝向改变，不等同真实 3D 植物阴影。原生 Rhino 显示模式的阴影不保证包含 conduit 植物；请以独立阴影通道为准。

本版为独立点锚点植物；不支持把植物封装进块后的递归显示/散布。PNG 以本地库路径引用，3dm 不嵌入完整植物库，跨电脑需一并传递库及保持路径。非植物裁切沿用当前不透明场景网格，不处理玻璃的光学透射。

## 验证

标准 Core 验证含朝向、透明边缘、建筑裁切、单株保留、交错物种合并、科学名称 PSD 嵌套和透空投影。B 测试入口 `Test-Plants.py`、`Export-Plants.py`、`Open-PlantFinal.py` / `Check-PlantFinal.py`、`Check-PlantJobs.py`。独立解码 `Verify-PlantPsd.py`，独立相机射线／源 PNG oracle `Extract-PlantOracle.py` / `Verify-PlantOracle.py`。真实生成会使用图像额度，不应无故重复。证据在 `artifacts/rhino-B/plants015`，不是 Photoshop UI 验证。
