# v0.4.1：曲面阴影准确性修正

2026-10-22，固定沙盒 B，仍使用 C# / CPU。命令继续为 `RhinoSceneFlowExportShadowVolumePSD`，MCP 继续用 `backend:"volume"`。没有新增服务、端口或鼠标操作，没有发布到正式 Rhino。旧 `ray` 后端保留作对照，其旧法线偏移漏影没有被标为修复。

## 已复现的问题

v0.4 阴影体解决了近接漏影，但在双曲面的明暗分界附近，三角网格面法线与原始曲面法线不一致，导致假自遮挡及断续碎影。阴影体与同一网格的射线查询几乎一致，不能证明其结果符合原始曲面。之前避开变化边界的 1,564 个采样无法覆盖这类问题。

在原测试双曲面的同一透视区域，独立解析参考检查 5,001 个像素，v0.4 有 82 个像素的 alpha 不符。放大对比见 `artifacts/rhino-B/accuracy/terminator-comparison.png`；原版 PSD 保留在 `artifacts/rhino-B/volumes/`。

排查也发现参考方法需要控制相切数值误差：CurveBrep 给出的初始交点估计可能偏离真实曲面。直接从估计点发出光线，会在极近处再次命中接收面。仅减小相交容差或增大光线偏移都不是可靠的解决办法。

## 修正方法

保留阴影体作为全画面的网格可见性计算，对几何不确定位置加入原始几何复核：

1. 读取场景时保留独立的 Brep/曲面/Extrusion 副本以及 Mesh 副本；块变换包含在快照中。所有查询使用相机附近的局部坐标，网格副本启用双精度顶点，导出后释放，不修改文档对象。
2. 在曲面法线变化、面法线与平滑法线不一致的明暗分界附近，以及曲面上网格判为阴影的位置，重新求相机到实际几何的最近交点和曲面法线。
3. 在阴影覆盖边界的两侧额外复核 3D 射线，修正网格轮廓使阴影落到错误接收面的问题。候选列表先冻结，再写结果，避免传播或图像形态学操作。输出由原始几何的查询结果决定，不使用模糊、阈值、填洞或删除小连通块。
4. Brep 使用尊重裁剪环的 CurveBrep。初始交点在所属原始面上用 ClosestPoint、PointAt、NormalAt 和沿射线的 Newton 修正收敛，同时验证三维残差与 trim 位置。不要换成 Rhino 8 RayShoot，它会忽略 Brep 的裁剪环，可能封住孔洞。[官方 RayShoot 文档](https://developer.rhino3d.com/api/rhinocommon/rhino.geometry.intersect.intersection/rayshoot)
5. 相切处按**射线方向上的交点误差**判断收敛：垂直残差需小于查询容差乘以法线与射线方向点积的绝对值。只用垂直距离，可能把光线起点当成一个实际位于起点后方的交点。
6. 光线只沿太阳方向前进显式 `bias`，不沿平滑法线或切平面误差移动。查询容差小于 bias，不把文档建模公差用作遮挡间隙。真实近接遮挡保留。

原始 Mesh 仍按其实际三角形查询，顶点法线只影响可选本体明暗；SubD 此阶段仍以生成的细分网格查询。没有宣称实现所有几何的解析求交。

## 独立参考与结果

测试双曲面由半径 3、高度 7、相差 120° 的两个圆作直纹面生成，其方程为：

```text
(x - 11)^2 + y^2 - (27/49)(z - 3.5)^2 = 2.25, 0 <= z <= 7
```

`Test-ShadowAccuracy.py` 对该几何使用二次方程求相机和光线交点，并用解析梯度计算法线，独立于生产 SurfaceRefiner。参考还支持地面、墙面、球体和马鞍面的解析求交，其它投影物仍用原始 Brep 检查。保留真实投射阴影。对样本的四个子像素分别计算预期，直接比较 PSD alpha，**不排除明暗边界样本**。

| 视图 / 光源 | 检查像素 | 子采样 | 部分覆盖边界像素 | 不一致 | 导出耗时 |
| --- | --- | --- | --- | --- | --- |
| 透视，太阳 [-.3,-1,1] | 5,001 | 20,004 | 43 | 0 | 11,932 ms |
| 俯视，相同太阳 | 2,221 | 8,884 | 42 | 0 | 20,156 ms |
| 透视，太阳 [1,-1,2] | 1,827 | 7,308 | 11 | 0 | 7,569 ms |

合计 9,049 个像素、36,196 个子采样；既包含阴影也包含亮面。相同透视区域的 v0.4 错误由 82 个降到 0。第一轮原始面复核仍有透视 13、俯视 1 个像素不符；补上相切收敛条件与轮廓两侧几何复核后归零。该轮失败文件保留在 `accuracy/iteration1/`。

最终 PSD 导出重新读取相同场景和视图；先逐字节确认色层 PSD 与参考采样时一致，再复用独立解析参考，避免为每次迭代重复求参考。独立解码结果见 `accuracy/verified.json`。复核脚本仍可完整重算参考。

另外验证了 2 个混合接收面的轮廓像素，每个 4 个子采样，均通过。这两个位置最初用 CurveBrep 直接作参考时会在墙面光线起点产生假命中；改用墙面、马鞍面和双曲面的解析方程后，确认新结果正确，避免把参考方法的假自相交当成产品错误。

另重新执行原始 1,564 个 Brep 稳定区采样，0 不一致。球面、双曲面、墙面、地面、带孔面场景、近接反例、半透明样式、135°/45° Rhino Sun、实际命令、默认 2048 输出及状态保留通过。解码结果在 `artifacts/rhino-B/volumes-v041/verified.json`。

近接反例中心仍为新后端 alpha=255、旧后端 alpha=0。默认 2048×1047 的这个测试场景约 34.1 秒，进行了 39,148 次原始几何复核；1024 透视复测约 10.6 秒。本轮接受增加的耗时，未用降低精度换取速度。

Core 验证通过，新增回归检查确保几何复核保留已知薄片阴影，并允许精确凸球保持无自身投射阴影。

## 精度边界

这次修复了已复现的双曲面碎影和边界错误，不构成任意模型、任意像素的数学精度保证。未进入复核候选区的区域仍用网格结果；网格完全漏掉的极小特征不会自动重建。原始几何求交受 Rhino 数值容差约束，小于 bias 的间隙仍可能合并。无效几何、极端相切、SubD 极限面和特殊变换还需要各自验证。

透明材质、植物 alpha 裁切、软阴影、裁剪平面、布局和隐式地面仍不支持。色层本身仍用网格，边缘可与原始曲面复核后的阴影存在微小覆盖差异。当前同步执行，会阻塞测试 Rhino；未做 GPU 或 C++ 迁移。PSD 通过外部解析器检查，没有启动 Photoshop。
