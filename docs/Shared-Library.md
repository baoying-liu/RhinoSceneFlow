# 本地共享材质库（v0.13.3）

材质库保存在 Rhino 文件之外。不同 `.3dm` 使用同一路径时，共享贴图、尺寸、名称、分类与标签；选择、UV、材质绑定、任务及聊天会话按文档 / Rhino 会话隔离。默认路径继续使用用户文档下的 `RhinoSceneFlow/Materials`，已选择的自定义库路径保留。旧库布局与 SchemaVersion 1 直接兼容，无需迁移或重新导入。

## 同机并发

- `.sceneflow-library.lock` 由操作系统独占打开，协调新版本客户端的读取和提交。进程结束自动释放句柄，锁文件保留；不靠删除锁文件或猜测 PID 解锁。线程内可重入，不能跨 await 持有。等待上限 3 秒，失败明确报错。
- 导入先在各自 GUID 的 staging 目录复制和校验图片，最后持锁发布完整目录。贴图不可变。元数据使用唯一临时文件、flush 和原子替换，避免共用 `.tmp`。本机同步目录压力测试出现过短暂 rename access-denied，提交最多重试 1 秒；持续失败仍报错，不改成覆盖写或删除旧数据。
- 尺寸 / 外观保存携带读取时的 revision 与 catalogRevision，旧编辑被拒绝，保留用户草稿。库属性编辑同样校验读取时 catalogRevision；MCP `material_update_labels` 提供 expectedCatalogRevision。未指定时在锁内读取最新资产并仅改标签字段，保留外观字段。
- 整库整理在锁内重新检查完整 ID 集与版本，再提交全部元数据。持锁读取看不到部分分类更新。提交前保存 `.sceneflow-catalog-rollback.json`；进程在提交途中退出，下次读取先恢复旧元数据。验证覆盖进程中止，没有扩大为断电或跨机器分布式事务保证。
- 材质包使用一份元数据快照和不可变图片，不在打包途中重新读取可能变化的 asset.json。

## 界面与会话

库页面约每 2 秒检查版本，自动更新列表、分类及标签，保留搜索、选择与未保存编辑。旧编辑保存时提示重新选择材质，不静默覆盖。修改库参数不直接改写模型中的材质绑定；重新应用使用当前资产版本。

ChatKit 临时数据为 `chatkit-data/sessions/<Rhino PID + 会话随机 ID>/doc-<序号>/<面板 ID>`。不同进程不会因相同文档序号共用后端数据、上传文件或 server.log。已有聊天数据保留。

## 验证

LibraryConcurrencyValidation 加入标准 Build：4 个真实独立写入进程导入 32 个材质、修改 80 次外观与 80 次标签，并行读者校验；两个读者与整库整理并发；过期编辑拒绝；实际中止持锁、部分写入的自有测试进程后恢复。断言精确版本计数及尺寸累加值，不只检查 JSON 可读。

B 通道用真实 PNG 和独立测试库，在 Rhino 面板运行时由两个外部进程写入：自动刷新到 17 个资产、保留草稿、UI / API 冲突拒绝、重新读取后保存、外部整理后旧尺寸编辑不覆盖新分类。新建文档后仍可访问同一批 17 个资产。测试后恢复原 B 库，原有 4 个材质保留。证据 `artifacts/rhino-B/shared-library0133`。

本轮是多个独立文件写入进程加一个 B Rhino，没有表述为两个 Rhino 实例的界面并发测试。保护适用于同机、同路径、采用此协议的客户端。
