# Rhino → Web UI 与操作流程审计（2026-11-10）

本轮使用家里 RhinoDevSandbox **B**，管理 MCP 19540、原厂 Platform 22801。修复版 **0.22.5**。所有模型写入和画板编辑均在独立 Hillside 副本进行；未操作系统鼠标、未部署正式 Rhino。本文区分实际模型、真实浏览器、合成回归与尚未验证的范围。

## 已修复

| 问题与触发条件 | 原行为 | 本轮处理 |
| --- | --- | --- |
| 旧案例恢复任务设置，再切换画布 | 旧 baseline 缺少 editScope 等默认字段；返回后自动保存被误判为修改锁定内容，出现 409 并阻断保存 | 恢复及备份配置按当前参数／标注 schema 规范化；实际浏览器覆盖“恢复 → 切换 → 保存” |
| 修改 AI 总开关／特殊层总开关后恢复 | 分组开关不在保存的配置里，恢复后仍是修改值 | 配置保存与恢复包括 AI 分组开关，兼容旧配置默认值；显示小眼睛保持不变 |
| 恢复之后的待生成状态 | 恢复本身改变 context，可能重新变黄；共享参考仍有变动时又可能给人已恢复的印象 | 对照已保存任务计算状态；共享画布内容未恢复时继续标记待生成 |
| 恢复操作名称及范围 | “撤销修改”易与 Ctrl+Z、整板回滚、PhotoCraft 参考层混淆 | 改为“恢复任务设置”，说明局部任务配置范围；共享画布使用撤销，PhotoCraft 当前参考层保留 |
| PSD 工具窄侧栏 | 尺寸行与复制按钮共享布局列，撑宽卡片并产生横向滚动 | 尺寸输入与操作按钮拆为独立布局；400 px 原生 Eto 内容检查无该横向溢出 |
| 删除参考图、撤销、继续操作 | 参考与标注区域因选择被清空而自动收起，撤销后操作仍隐藏 | 展开状态独立保存于页面；删除、取消选择不强制收起；参考图库真实浏览器回归通过 |
| 输入框中 Ctrl+R | 抢走输入上下文，执行整板重做 | 输入／原位文字编辑时不触发整板快捷键 |
| 生成前不了解输出尺寸 | 整图与高清的尺寸含义不明确 | 预检返回并显示准确回填尺寸；明确整图沿用输入像素，放大使用高清输出 |
| UI 版本号 | 页脚写死旧版本，与运行服务不同 | 从前端构建版本生成，不再手写页脚版本 |

恢复方案比较：整板强制回滚会牵连其他图片共用的素材／标注；本轮采用明确命名的任务配置恢复，共享编辑通过既有撤销恢复。它不会偷偷删除其他图片的参考资源，也不声称能恢复 PhotoCraft 的旧像素。

## 实际走过的流程

| 环节 | 本轮证据与结果 |

| 植物隔离编辑 | 12 次实际 Eto 双击事件进入；15 株透明拾取；视口双击重入和空白双击退出；锁定标记清理通过 |

| 文档生命周期 | 同一 PID 19276 两轮 New/Open，八工具最终重绑定新文档，无崩溃。打开后存在约一秒延迟绑定及 Platform 连接重置，测试只重试只读状态轮询，不重复提交命令 |
| Named View → PSD | 实际 600×450：植物／阴影／材质贴图／Arctic，8.55 秒导出；独立 psd-tools 读取 13 个图层（含 Group），核对阴影 Multiply/45%；视口、选择、物件保持 |
| Rhino → Web | 原生后期入口提交该 PSD 快照，解析完成后进入独立画板；文件 SHA 未变化 |
| 真实 AI 整图 | 在实际页面完成检查与确认；1 次真实生图，约 53.76 秒，原生返回 1254×1254，工作台回填 600×450；新文件 receipt/hash 验证通过。完成后锁定结果、清空未改变的根模板描述 |
| PNG／工程保存 | 实际 PNG 导出；完整 sflowboard ZIP 校验及两个节点图片资产包含检查通过 |
| 对比 | 实际结果拖杆从 50 移动到 63；平滑模式保留拖杆 |
| PhotoCraft | 真实固定版 Web/Wasm 绘画两次、返回／重开／替换、取消、特殊图层 roundtrip、过期拒绝、JSON 文件回传均通过，未用系统鼠标 |

真实 AI 输出独立像素检查：**48,807 个只读像素逐字节不变、alpha 全部一致**；200,497 个像素有变化。这是保护像素与来源检查，不是建筑几何完全正确的证明。所选描述是保留结构并细化材质，源模型本身已贴图，因此视觉变化相对克制。本轮没有再次生成 4K。

浏览器分离 fixture 最终十条流程通过：九工具／笔压力与取消、标注移动缩放与笔宽、中文原位文字、空间考虑框、删除与恢复、参考图库双向选择与转换、局部／整图范围、整图／高清草稿及预检、旧配置恢复、参考层显示。旧脚本的按钮、折叠区和 board.marks 断言已更新；不是改产品去迎合旧断言。首次失败与重跑记录分别保留。

## 需要下一轮关注的整体体验

1. **Rhino 到 Web 的交接仍偏文件导向。** 可以将“导出成功 → 送入当前画板／新画板”作为导出后的明确动作，携带导出视图与文件版本；现有独立文件导入仍保留。减少刷新文件列表、再次找 PSD 的操作。还未新增这一跨工具动作。
2. **语言设置边界不统一。** Web 语言、植物中英文名、其他原生面板的中文标签属于不同设置；需要统一用户可理解的语言范围，同时保留拉丁学名和用户文件名。未对原生所有标签进行全面国际化。
3. **显示与生成设置仍需更清楚分组。** “AI 结果混合比例”属于预览／导出像素混合，不是生图强度；可以把显示选项独立放置，进一步减少内容锁定与显示控制的联想。未改变这些既有参数语义。
4. **新组合空状态可以更简洁。** 无植物时应更突出“先添加植物”，弱化暂时没有作用的权重／间距输入；高频参数保留，边缘曲线和全局朝向继续按需展开。
5. **真实 AI 质量需要场景集。** 小案例只覆盖轻量建筑地形与 15 株植物；大型场景的交互延迟、复杂拓扑 UV、真实手绘屏硬件与不同 Rhino 版本，不能由本轮推断全部通过。生物检索／材质与植物新生成的 AI 质量未在本轮重新抽样。

## 保存与测试边界

- 原始 .3dm 校验值及原两份 board.json 保持，最终恢复用户 Web 偏好；审计画板独立保留。
- 直接 SDK WriteFile 覆盖当前打开文件曾返回“文件无法打开”；模型 Modified=false、原副本存在。未将该测试方式计作常规保存通过，也未归咎为插件崩溃；生命周期测试使用已存在且未修改的独立副本。
- 选中测试曾与另一项材质测试交叉改变选择，首次失败无效；已顺序重跑五阶段通过。PhotoCraft/特殊层测试最初误复用已绘画 fixture，已用独立新 fixture 重跑。
- 本轮只读 Computer Use 用于确认保存等待阶段的 B 窗口；没有激活或发送系统键鼠输入。其余主要使用原厂 MCP、文件检查和无界面 Edge。
- 全构建／Core 验证通过；新恢复回归、任务输入、画布上下文、栅格稳定性、工作流、参考图库、取消、门控及 PhotoCraft 回归通过。
