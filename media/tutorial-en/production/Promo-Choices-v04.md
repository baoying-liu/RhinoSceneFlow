# Transition and style choices v04

A 25-second transition selection reel, five independent five-second clips, and five actual SceneFlow whole-image styles generated from the same 1280×720 human-view PSD. This is a selection study, not a new final introduction film.

Transitions: A match push for object material changes; B blur/whip slide for short rhythmic cutaways; C layer fly-through for PSD channel reveal; D angled mask reveal for source-to-render; E perspective paper peel for tactile/printed style sections. Prefer a small consistent subset in the final edit. These are editorial effects, not product UI actions or evidence of realtime viewport performance. Do not use an ornamental transition as the result stability comparison.

New images: photographic daylight, cinematic dusk, watercolor with linework, paper collage, graphite/tonal wash. All five are independent completed real generation tasks through sandbox B's original Platform / SceneFlow Web workflow. All share one original PSD and frozen task inputs; no recoloring filter was substituted for generation. Original source files are preserved. No image cropping or white-pixel heuristics were applied. Dimensions are 1280×720; measured outer-edge near-white pixel fractions are zero for all five, and outputs were visually reviewed. Architectural appearance can be redrawn; PSD guides and prompts are guidance, not hard geometry constraints.

Real workbench comparison: five screenshots of the native Compare divider plus two three-second frame-stepped browser recordings (daylight and collage). These are actual Web UI, not an imitation viewer. No user's desktop mouse was controlled. The owned headless browser used English preferences via isolated request interception; global preferences were not changed. Source provenance and completed tasks are retained in the exported .sflowboard.

Audio: existing original SceneFlow procedural music plus a deterministic synthesized whoosh from make-transition-sfx.py, timed to each transition. No third-party recordings, paid music generation or license service was activated. Image generation uses the existing configured AI account/quota.

Validation: ESLint/TypeScript passed. Fifteen representative transition frames rendered; a disappearing-plane gap found during QA was fixed before final export. Final H.264/AAC reel is 1920×1080 at 30 fps (750 video frames); complete FFmpeg decode passed. Browser decoded ten images and metadata for all eight videos, and seeking passed on the reel, layer clip and both actual Web slider clips without media errors. Gallery selection is local to the browser. Local OneDrive files are written; remote cloud synchronization is not verified.

Rebuild: restore the prior editable project and revision-v03 overlay, then overlay the delivered Source folder. Keep public/case/promo-20261112, promo-revision-v03 and promo-styles-v04 assets. Run npm ci, npm run lint, then select Transition-Showcase-v04 in Studio. The original soundtrack can be rebuilt using make-film-score.py; the small whoosh is included and reproducible. Let Remotion use its bundled browser. No new plugin version or production Rhino installation was made for this media task.
